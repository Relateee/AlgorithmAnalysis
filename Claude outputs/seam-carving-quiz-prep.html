    Know these cold

    The facts most questions lean on. Read this first, then test yourself below.

    Energy (Gradient)|I(r,c+1)−I(r,c−1)| + |I(r+1,c)−I(r−1,c)|, on grayscale, border pixels replicated (clamped).
    Energy (Sobel)|Gx| + |Gy| with handwritten 3×3 kernels [−1 0 1; −2 0 2; −1 0 1] and its transpose.
    DP recurrenceM(1,j) = e(1,j); M(i,j) = e(i,j) + min M(i−1,k), k ∈ {j−1, j, j+1} in range. Answer: min_j M(m,j), then backtrack through the parent table.
    Tie-breakingLeftmost everywhere: DP parent, DP last row, greedy start and greedy steps.
    Number of seamsAt least 2^(m−1) from one start pixel (each pixel has ≥ 2 successors when n > 1), so exponential in m.
    DP costO(HW) time per seam, O(kHW) for k seams. Parent table O(HW); rolling rows cut the cost table to 2 rows (O(W)), but parents stay O(HW).
    GreedyFind O(H) per seam, but the whole carve is O(kHW) because energy is recomputed every time. Report: find 120–280× faster, whole carve only about 2× faster, seams cost 1.7–3.7× more.
    Graph cutInfinite reverse edges: one cut per row. Infinite diagonals: connected seam. Seam = rightmost pixel of the source side S in each row. The last column is joined to the sink with infinite capacity, so it can never be removed: seams use columns 0 to n−2.
    Max-flowEdmonds–Karp O(VE²), Dinic O(V²E). The graph is sparse (E = Θ(V), V = HW + 2), so both are O((HW)³) worst case. Measured on the tower: graph cut 868–2,019× slower than DP per seam, and its seams cost 2–3% more because it cannot use the last column.
    Resize orderAll vertical seams, then all horizontal. Horizontal seams = vertical seams of the transposed image. Shrinking only; no seam insertion.
